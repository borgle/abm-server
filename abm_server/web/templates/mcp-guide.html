AGENT MANUAL

ABM Server MCP Guide

A complete integration guide for agents and MCP client maintainers. ABM connects a user's own Chrome browser to MCP; browser actions run locally in the extension while the server handles authentication, routing, and audit.

Protocol: Streamable HTTP Authentication: OAuth 2.1 Endpoint: {{ issuer_url }}/mcp

1. Quickstart

1.1 Install the Chrome extension

The ABM extension is not yet on the Chrome Web Store. Download the latest ZIP from GitHub Releases, unzip it, enable Developer mode at chrome://extensions, then click "Load unpacked" and select the extracted folder.

1.2 Create an account

Register through the website, or call the public MCP endpoint with the account_register tool: 

POST {{ issuer_url }}/mcp/public
Content-Type: application/json
Accept: application/json, text/event-stream

{"jsonrpc":"2.0","id":1,"method":"initialize","params":{
  "protocolVersion":"2025-03-26",
  "capabilities":{},
  "clientInfo":{"name":"agent","version":"1.0"}
}}

The public endpoint exposes only account_register. If registration approval is enabled, new accounts are pending and must be approved by an administrator in the console.

1.3 Connect the browser extension

  1. Sign in to the console.
  2. Create an API Key. The plaintext is shown only once, so save it immediately.
  3. Open the extension options page, enter the server URL (for example {{ issuer_url }}) and the API Key.
  4. Click Connect and confirm the extension is online. OAuth-authenticated browser tools acquire an exclusive connection through a browserSessionId.

2. Authentication

2.1 OAuth 2.1 (recommended)

When an MCP client connects to {{ issuer_url }}/mcp, it receives 401 and WWW-Authenticate. The client should read the protected resource metadata, discover the authorization server, and complete dynamic client registration, the PKCE authorization-code flow, and token exchange. 

Protected Resource Metadata:
{{ issuer_url }}/.well-known/oauth-protected-resource/mcp

Authorization Server Metadata:
{{ issuer_url }}/.well-known/oauth-authorization-server

Scopes:
browser         Run browser tools through the extension
account:read    Read account, plan, and API key metadata
account:write   Create/revoke API keys and update account settings

The authorization flow opens the ABM sign-in page. After sign-in, a consent page shows the client name, scopes, and browser connections this client may use. Browser tools acquire an exclusive connection through a server-issued browserSessionId; a connection already held by another task returns ABM_CONNECTION_BUSY.

2.2 Authentication failures

Authentication failures return 401 with the following response header: 

WWW-Authenticate: Bearer resource_metadata="{{ issuer_url }}/.well-known/oauth-protected-resource/mcp"

5. Examples

5.1 Read account information

{"jsonrpc":"2.0","id":10,"method":"tools/call","params":{
  "name":"account_me",
  "arguments":{}
}}

5.2 Create an API Key

{"jsonrpc":"2.0","id":11,"method":"tools/call","params":{
  "name":"api_key_create",
  "arguments":{"name":"Agent browser"}
}}

The plaintext field in the response is shown only once; write it to the extension or a secret manager immediately.

5.3 Browser actions

{"jsonrpc":"2.0","id":12,"method":"tools/call","params":{
  "name":"browser_navigate",
  "arguments":{"url":"https://example.com","reuse":"site"}
}}

6. Errors and recovery

Error codeMeaningSuggested action
ABM_INVALID_TOKEN Missing, invalid, or expired OAuth token Sign in and authorize again
ABM_SCOPE_REQUIRED OAuth token is missing a required scope Re-authorize and grant the required permissions
ABM_EXTENSION_OFFLINE No online extension connection Enter the key in the extension and connect
ABM_CONNECTION_BUSY The target browser connection is in use by another browser task Wait for the other task to finish or retry later
ABM_BROWSER_SESSION_REQUIRED A browser task handle is required Call browser_open_session first
ABM_BROWSER_SESSION_INVALID The browser task handle is invalid or expired Open a new browser session
ABM_KEY_LIMIT_REACHED API Key limit for the plan reached Revoke an old key or upgrade the plan
ABM_ACCOUNT_PENDING Account is awaiting approval Wait for administrator approval
ABM_ACCOUNT_DISABLED Account is disabled Contact an administrator
ABM_RATE_LIMITED Too many requests Wait according to retryAfter

7. Security boundaries

  • API Keys are stored only in extension local storage and as a server-side digest; they are never exposed to page scripts.
  • Dynamically registered OAuth clients use the PKCE public-client flow and are not issued a client secret.
  • OAuth tokens are stored only as SHA-256 digests and support expiry, revocation, and refresh rotation.
  • Browser tools must run through the user's online extension; the server does not store account passwords or page cookies.
  • Administrator actions create audit events; disabling an account revokes sessions and OAuth tokens and closes the extension connection.
  • Production deployments must use HTTPS and set ABM_PUBLIC_BASE_URL or ABM_OAUTH_ISSUER_URL.

8. Troubleshooting

MCP client does not open the sign-in page

Check that the client supports OAuth and Streamable HTTP, and confirm that /mcp returns 401 with WWW-Authenticate. If the client only supports API Keys, configure the Bearer header directly.

Browser tools report that the extension is offline

OAuth sign-in only authenticates the MCP connection; browser tools still require an online extension. Create an API Key in the console and connect from the extension, or verify that an online connection already exists.

Token is still invalid after authorization

Check the server clock, confirm that ABM_OAUTH_ISSUER_URL matches the URL used by the client, and verify that the account status is active.
